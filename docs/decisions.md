# Решения

Текущий набор решений в силе. Одна запись на решение; когда решение меняется —
запись правится на месте, историю держит git.

## parse

### Дефолтные значения параметров

Decided: `parse()` дозаполняет `params` дефолтами объявленных параметров — после
разбора аргументов, только для тех имён, которых в `params` ещё нет, со
приведением к типу параметра. Дефолт из паттерна (`--concurrency -c number 4`)
конвертируется в момент `.param()`, поэтому `Param.defaultValue` хранит уже
типизированное значение, а негодный дефолт падает на месте объявления, а не при
разборе чужой командной строки.

Because: грамматика `--name [-s] <type> [default]` обещала это в README, и оба
потребителя с параметрами — claww и dispute — написали дефолт в паттерне раньше,
чем выяснили, что он не работает. Их `??` и `||` в коде — след бага, а не выбор.

Not chosen: выкинуть дефолты совсем и оставить их приложению
(`params.format ?? "md"`). Честнее по информации — `undefined` означал бы «не
передавали», и `params` оставался бы протоколом argv. Отвергнуто: требует
вычистить `[default]` из грамматики, README и шести объявлений, а выигрыш
проявляется только в сценарии «CLI поверх конфиг-файла», которого нет ни в
dapes, ни в claww, ни в dispute.

Known cost: `params` не различает «передал `-c 4`» и «промолчал». Если появится
конфиг-файл под CLI, подставленный дефолт будет молча бить значение из конфига —
понадобится провенанс значения (`ValueSource` у clap,
`getOptionValueSource` у commander).

Deferred: печать дефолта в `--help`. У claww руками вписаны в описания только
вычисляемые дефолты (`stdout`, `cwd`, `claww.out.<ext>`), которые статический
литерал в паттерне не удержит; у `--format string md` со статическим дефолтом
в описании ничего не вписано. Спрос не доказан.
